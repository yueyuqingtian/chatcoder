## 1. 产品概述

### 1.1 产品定位
chatcoder 是一款面向开发团队的 **AI 多 Agent 协同编码工作台**。它把"产品 → 设计 → 开发 → 测试"的研发流程，具象化为一个**可配置的 AI 开发小组**：多个 Agent 以群聊形式分工协作，完成从需求到交付的全流程。

与单 Agent 编码工具（Cursor / Copilot）的本质差异：核心卖点是**团队级协同**——有分工、有交接、有讨论、有审核，模拟真实研发团队。

### 1.2 目标用户
- **独立开发者**：希望拥有一个"AI 开发团队"，跑通全流程交付。
- **小型创业团队**：人手不足，用 AI 小组补齐产品 / 设计 / 测试能力。
- **企业研发团队**（后期）：标准化流程、知识沉淀、多成员协作。

### 1.3 核心价值主张
1. 多 Agent 群聊式协作，模拟真实团队。
2. 智能编排：一句话需求 → 自动组队 + 任务拆解。
3. 全流程覆盖：产品到测试一站式。
4. 知识沉淀：项目经验可复用。
5. **异构模型分工**：强模型规划、快模型执行，兼顾质量与成本。

## 2. 系统架构概览

chatcoder 采用 **C/S 架构**，核心原则：**服务端负责编排与调度，客户端负责执行与本地推理**。

### 2.1 组件
- **客户端（Electron + React）**：群聊工作台 UI、Monaco 编辑器、团队 / 任务管理；内含 **客户端 Agent 运行时**（本地工具执行 + 本地 agent 推理循环 + BYOK 模型直连）。
- **服务端（MVP：Python 单后端 FastAPI）**：任务编排、会话与发言权调度、RAG、持久化、模型网关（默认模型）。
  - **预留 Java 网关拆分点**：当并发 / 多租户压力出现时，可将"网关与治理"层拆为 Java 服务，MVP 阶段不实现。

### 2.2 模型调用双路径（v0.2 关键修正：方案 A）
- **默认模型**：客户端 agent loop → 服务端网关 → 默认模型（服务端代理）。
- **BYOK 用户自配模型**：**agent 推理循环在客户端运行**，客户端直连用户 baseURL，**token 流不经服务端**。

> **核心修正**：BYOK 场景下，agent 的"思考-决策-调用工具"循环（agent loop）**整体在客户端执行**，服务端只负责任务编排（拆解 / 调度 / 会话管理），不参与模型 token 流。这彻底解决了"编排器在云端、模型在本地"的多跳延迟矛盾，同时保护密钥、降低服务端带宽与成本。

### 2.3 多租户
MVP 先单租户，数据模型预留 `tenant_id`。

## 3. 功能需求

### 3.1 群聊协作模块（核心）

#### 3.1.1 会话模型
- 一个"项目群" = 一个会话（session）；群成员 = N 个 Agent + 用户。
- 群拥有**共享上下文**（工作记忆）：需求、决策记录、当前任务 DAG、关键产物引用。

#### 3.1.2 消息类型

| 类型 | 用途 |
|---|---|
| 文本 | 发言、讨论、提问 |
| 代码块 | 带语言标记，可"一键应用"到本地 |
| 任务卡片 | 任务分配 / 状态变更 |
| 决策卡片 | 关键决策留痕，用户可确认 / 否决 |
| 产物卡片 | 文件 / 设计稿 / 文档的引用与预览 |
| 工具调用 | 本地工具执行过程（可折叠查看） |
| 审批请求 | 高风险操作需用户批准 |

#### 3.1.3 @提及与消息路由
- `@agent名`：定向触发；`@team`：广播；`@user`：agent 向用户提问。
- 无 @ 的消息：由 **Leader 决定路由**给谁。

#### 3.1.4 发言权调度（关键难点）
- **令牌制**：同一时刻仅持令牌者可发言。
- **轮次上限**：单 agent 连续发言 ≤ N 轮必须交棒。
- **静默退出**：任务完成或无新输入时进入静默。
- **用户优先**：用户发言随时打断、获取控制权。
- **预算熔断**：单任务 token 超阈值自动暂停。

#### 3.1.5 上下游产物交接
上游产物自动挂到下游任务；**产物带版本**，上游返工时下游收到变更通知，避免使用过期版本。

#### 3.1.6 冲突与决策
分歧时：Leader 裁决 / 多 agent 投票 / 上报用户；关键决策引入 **"魔鬼代言人"机制**——强制列出反对意见，避免 LLM 从众。决策落"决策卡片"可回溯。

#### 3.1.7 用户介入
随时发言、@调整方向、暂停 / 接管任务、审批高风险操作。

#### 3.1.8 群聊子会话（v0.2 新增，防消息爆炸）
- **主群**只展示**关键节点**：任务分配 / 决策 / 产物 / 审批 / 完成。
- 细节讨论（agent 间的来回沟通、工具调用过程、思考流）下沉到**任务级子会话（thread）**，可折叠收起。
- 用户可展开任一任务的 thread 查看完整过程，避免主群被刷屏。

#### 3.1.9 上下文可见性模型（v0.2 新增，防 token 爆炸）
每个 Agent 的 prompt 上下文按三层组装：
1. **全局摘要**：所有 agent 共享的会话级摘要（需求、关键决策、当前进度）。
2. **任务相关**：@自己或所属任务的消息与产物。
3. **主动检索（RAG）**：按需从知识库检索补充信息。
- 默认**不注入全量历史**，控制 token 与成本。

### 3.2 Agent 角色与团队管理

#### 3.2.1 角色模板库（开箱即用）
产品经理、架构师、UI/UX 设计师、前端工程师、后端工程师、数据库工程师、测试工程师、DevOps、代码审查员。

#### 3.2.2 Agent 配置项

| 配置 | 说明 |
|---|---|
| 身份 | 名称、头像、职位 |
| 系统提示词 | 职责定义（核心） |
| 职责范围 | RACI：负责什么、协作什么 |
| 工具白名单 | 该 agent 允许调用的本地工具 |
| **绑定模型** | 用哪个模型（默认 / BYOK / 第三方），见 3.7 |
| **运行位置** | 客户端本地（BYOK）/ 服务端（默认模型可选） |
| 参数 | 温度、max_tokens |
| 知识领域 | 关联哪些知识库 |
| 协作风格 | 保守 / 积极 |

#### 3.2.3 团队管理
创建小组 → 指定 Leader → 定义全流程编排阶段 → 保存为**小组模板**复用 → 支持**智能组队**（输入项目类型自动推荐组合）。

#### 3.2.4 Leader 角色
接收需求 → 拆解任务 DAG → 分配任务 → 调度发言权 → 汇聚产物发起审核 → 冲突裁决。

### 3.3 智能编排与任务流

#### 3.3.1 智能组队（一键生成）
用户输入项目描述 → 系统分析所需角色 → 推荐 agent 组合 → 一键拉群。用户可增删调整。

#### 3.3.2 需求分析与任务拆解（Leader 核心职责）
Leader 接收需求后输出：需求理解、任务列表（含验收标准）、任务 DAG、分配方案。拆解结果以"任务卡片"群发，**用户确认 / 修改后才执行**。

#### 3.3.3 任务状态机
`待启动 → 进行中 → 待审核 → 已完成 / 已驳回(返工)`，外加 `阻塞(blocked)` 态。

**v0.3 补充**：Leader 拆解后任务统一进入 `pending` + `session.plan_confirmed=false`，
用户确认（`POST /sessions/{id}/plan/confirm`）后才解锁调度。
默认硬门；`AUTO_CONFIRM_PLAN=true` 时自动确认开跑。

#### 3.3.4 任务调度
按 DAG 拓扑序调度，无依赖任务可并行。

**v0.3 实现**：`SessionScheduler` 取入度 0 且 `pending` 且 `plan_confirmed` 的任务，
`asyncio.gather` 同层并行执行；每任务完成后 `decrement_indegree_and_pick_ready` 解锁下游。
原"调度器与发言权联动"在 v0.3 暂停（与并行执行冲突），改为 `BudgetTracker` 预算熔断。

#### 3.3.5 DAG 运行时动态变更（v0.2 补充）
DAG 支持 **insert / cancel / replan**：返工、新增需求、任务失败时可动态修改，变更触发重新调度。

#### 3.3.6 动态扩容
执行中发现缺角色，Leader 可"邀请"新 agent 入群。

- **规范库** / **经验沉淀** / **RAG 检索**。

### 3.5 编码工作台
- Monaco 编辑器 + 文件树 + 终端（受安全沙箱限制）。
- Git 集成（提交、分支、Diff）。
- **Diff 预览与合并**：agent 产出以 diff 呈现，用户 review / 合并 / 回滚。
- **并发文件锁（v0.2 修正）**：单客户端多 agent 场景下，文件锁由**客户端进程内**管理（无需分布式锁），写操作前 acquire 同路径锁，冲突上报。

#### 3.5.1 安全沙箱信任模型（v0.2 新增 / v0.3 调整）
- 桌面端为**软沙箱**：工作目录限制 + 路径防穿越 + 命令白 / 黑名单 + 高风险审批。
- **明确信任边界**：agent 理论上可"写脚本再执行"绕过白名单，因此采用**用户自担风险 + UI 强提示 + 回收站 / 快照兜底**模型；后期可接 WSL / Docker 做硬隔离。
- 该风险须在产品首次启动时向用户明确告知。

> **v0.3 调整（用户决策）**：本期采用**仅审批门**沙箱策略——不做命令白名单，
> 工作区根目录限制 + 路径防穿越 + 所有副作用工具（fs.write / terminal.exec / editor.apply_diff / web.fetch）
> 一律经 `ApprovalManager` 阻塞审批；fs.read / fs.list 免审批但仍做路径防穿越。
> 命令白名单与硬隔离留 v0.4+。

### 3.7 模型管理（异构模型分工）

#### 3.7.1 核心理念
**不同 Agent 可绑定不同模型，按智能等级分层**：高智能模型做规划 / 决策，低成本快速模型做执行。

#### 3.7.2 模型智能分层

| 等级 | 定位 | 典型用途 | 示例 |
|---|---|---|---|
| L3 规划级 | 高智能、强推理 | 需求分析、任务拆解、架构、决策 | DeepSeek-v4-pro、GLM-5.2、Claude |
| L2 执行级 | 均衡 | 模块开发、接口实现、文档 | DeepSeek-v4-flash、GLM-5.2 |
| L1 轻量级 | 快速、低成本 | 简单重复、格式化、摘要 | 小参数 / fast 系列 |

#### 3.7.3 模型来源与运行位置（v0.2 修正）
| 来源 | 密钥位置 | agent loop 运行位置 | 模型调用路径 |
|---|---|---|---|
| 系统默认 | 服务端 | 可选客户端 / 服务端 | 经服务端网关代理 |
| 用户 BYOK | **客户端本地加密** | **客户端** | **客户端直连 baseURL，不经服务端** |

#### 3.7.4 路由策略
- 按 agent 角色自动推荐模型等级（可覆盖）。
- 支持任务级临时切换模型。
- 模型不可用 / 超时自动降级到同等级备用。

#### 3.7.5 模型管理界面
模型列表（来源 / 等级 / 上下文 / 单价）、新增 BYOK（填 provider / baseURL / apiKey，仅存客户端）、绑定关系。

### 3.8 质量保障（v0.2 新增 / v0.4 实现）
- **Review 门禁**：代码审查员 agent 必须通过，产物才能合并；可选人工 review。
- **CI 门禁**：测试 / 构建 / lint 自动执行，失败拦截合并。
- **测试 agent**：生成测试用例并本地执行验证。

> **v0.4 实现**：
> - 新增 `ci.run` 工具(medium risk),reviewer agent 可调用运行 lint/test/build 客观验证。
> - 新增 [review.py](../server/app/orchestration/review.py) `review_task`:任务进入 `in_review` 后自动触发
>   同团队 `role=reviewer` 的 agent,用 ci.run/fs.read 审查产出。
> - reviewer 输出首行 `PASS` → 任务 `done`;`REJECT` → `rejected`(返工);默认 PASS 不阻塞流程。
> - reviewer 模板默认白名单已含 `ci.run`、`fs.read`、`fs.list`。
> - 测试覆盖:78 个 pytest 单测覆盖 DAG / 调度 / 审批 / 工具 / 审查等核心编排逻辑。

### 3.8.1 知识库（v0.5 实现）
- **知识库 CRUD**：创建 / 列表 / 详情 / 删除知识库（KnowledgeBase）。

- **关键词检索**：MVP 阶段用 SQL `ILIKE` 做简单全文检索，后续接向量检索。
- **示例知识库**：开箱自带"项目规范库"，含代码风格规范、Git 提交规范、架构设计原则。

> **v0.5 实现**：
> - 新增 [knowledge_service.py](../server/app/services/knowledge_service.py)：知识库与文档的 CRUD + 关键词检索。
> - 新增 [knowledge.py](../server/app/gateway/routers/knowledge.py)：REST API 路由。
> - 种子数据新增示例知识库 + 3 篇规范文档。

### 3.8.2 智能组队（v0.5 实现）
- **项目类型模板**：5 种预设团队配置（Web 应用 / 后端服务 / 前端 / 极简全栈 / 数据 AI）。
- **一键生成团队**：选择项目类型 → 自动创建 Team + 对应角色 Agent + 设定 Leader。
- **推荐工作流**：每种项目类型附带建议的开发工作流阶段。
- **角色模板扩充**：从 6 个角色扩展到 11 个，新增 UI/UX 设计师、全栈工程师、DevOps、数据科学家。

> **v0.5 实现**：
> - 新增 [smart_team_service.py](../server/app/services/smart_team_service.py)：智能组队服务 + 5 种项目模板定义。
> - 新增 `POST /api/teams/smart-create`、`GET /api/team-profiles` API。
> - 种子数据新增 5 个角色模板：ui_designer / fullstack / devops / data_scientist。

### 3.8.3 跨数据库兼容（v0.5 改进）
- 所有数据模型的 JSONB / ARRAY 类型替换为 SQLAlchemy 通用 `JSON` 类型。
- PostgreSQL 下自动映射为 JSONB（性能无损），SQLite 下映射为 TEXT 存储 JSON。
- 测试环境（SQLite in-memory）与生产环境（PostgreSQL）均可正常运行。

## 4. 非功能需求

| 维度 | 要求 |
|---|---|
| 安全 | 软沙箱（工作目录 + 命令白黑名单 + 审批）；明确信任边界；BYOK 密钥加密存客户端不上传 |

| 可靠性 | WS 通道 tool_call 唯一 id + ACK + 幂等 + 去重；任务 checkpoint 与断点续传；断线状态同步 |
| 性能 | 服务端异步编排；WebSocket 推送；LLM 流式输出 |
| 成本 | token 监控（任务 / agent）；默认模型服务端权威计费；BYOK 用量为客户端非权威上报 |
| 可观测 | agent 思考过程透明可见；完整执行日志可回溯 |

## 5. MVP 范围与路线图（v0.2 修正）

**MVP 目标**：用最小技术栈，最快验证"多 agent 群聊协作产出代码"核心体验。

**MVP 技术栈**：**Python 单后端（FastAPI 兼顾网关 + 编排）** + 极简 Web UI + 2 个 agent + 简化群聊 + 一个真实小任务。Java 网关 / Electron / 多租户暂不进 MVP，但接口预留拆分点。

| 阶段 | 内容 |
|---|---|
| Phase 0 地基 | monorepo；Python 单后端骨架（FastAPI）；单 agent 跑通一次 LLM（默认模型） |
| Phase 1 持久化与通道 | 会话 / 任务落 PostgreSQL；WebSocket 通道（含幂等） |
| Phase 2 ★多 Agent 群聊 | 2 agent（Leader + 执行）；Leader 拆任务 DAG；发言权调度；主群 + 子会话；WS 实时推送 |
| Phase 2.5 BYOK | 客户端 agent loop；BYOK 模型直连；异构模型路由 |
| Phase 3 扩展 | RAG；质量门禁；Electron 桌面端；**Java 网关拆分**（当并发需要时）；多租户 |

> **MVP 交付 = Phase 0 + 1 + 2**（先用默认模型验证核心），Phase 2.5 起接入 BYOK。

> **v0.3 状态（2026-07-25）**：Phase 2 端到端闭环已完成——并行层 DAG 调度、
> 真实 agent loop（工具循环 + 产物）、完整工具集 + 审批门沙箱、建表种子、模型/团队配置 UI、计划确认硬门。
> Phase 2.5（BYOK 客户端下沉）为下一版本主题。

## 6. 术语表

| 术语 | 含义 |
|---|---|
| Agent | 具备角色与职责的 AI 成员 |
| Leader | 小组中负责拆解任务、调度协作的主 Agent |
| agent loop | agent 的"思考-决策-调用工具"推理循环 |
| 群聊会话 | 多 Agent + 用户协作的会话容器 |
| 子会话（thread） | 任务级详细讨论的折叠子区，防止主群爆炸 |
| 上下文可见性模型 | 定义每个 agent 能看到哪些上下文的三层模型 |
| 任务 DAG | 任务的有向无环依赖图 |
| 发言权调度 | 控制群内 agent 发言顺序与轮次的机制 |
| BYOK | Bring Your Own Key，用户自带模型密钥 |
| 异构模型分工 | 不同 agent 绑定不同智能等级模型协同工作 |
| 产物交接 | 上游 agent 产出传递给下游 agent 的机制 |
| 软沙箱 / 硬隔离 | 桌面端路径+白名单限制（软）/ 容器级隔离（硬） |
| RACI | 负责 / 参与 / 咨询 / 知会 权责矩阵 |
