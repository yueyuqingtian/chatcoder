日期：2026-11-01。版本保持 0.10.0。保留开始工作时已有的未提交修改。

## 已交付

- 消息按 ID 游标、条数与约 1MB 软预算加载；正常切回仅取新增，历史改写通过修订号重新校验已加载区间。原全量接口保留兼容。
- 支持主线程/子代理搜索全历史、加载更多结果、按消息或轮次定位。跨页补齐工具调用与轻量续跑边界。
- 轮次虚拟列表继续保留；长正文、展开工具过程、代码和表格内部按可见区域挂载，共用同一纵向滚动容器。代码/表格复制使用完整数据。
- 流式扫描保留行游标、围栏及表格状态；稳定封块不在每次小增量时重新映射。大代码高亮使用 Worker，缓存同时约束条数、文本和节点规模。
- 拖拽宽度仍直接由 rAF 写入，实时折行；恢复按依赖与 4ms 预算分帧，新运动取消旧恢复。
- 隐藏子代理暂停视觉订阅与计时；最近五个非活动冷会话保留热视图，运行中的数据不淘汰，终端和浏览器生命周期独立。
- 子代理内容标题与顶部标签统一 IxBot；标题可两行显示，统计进入详情；默认面板宽度 260/400，仅影响无旧偏好的用户。长用户消息给出明确展开文案。
- 弹窗新增 compact/form/wide 三档，显式 width 继续优先；设置页面板按需加载；无模型时提供配置入口。
- WS 每连接有界队列与单发送者；同源连续增量可合并，终态/落库事件为顺序屏障。慢连接断开恢复，重放独立背压；全局消息只转发所需摘要。

## 后端基准

命令：在 server 目录执行 `.venv/Scripts/python.exe tools/benchmark_message_window.py`。脚本只创建临时 SQLite，不访问真实数据库。预热一次，有效采样三次取中位数；测量包含查询、DTO 和 JSON 序列化，不含浏览器和网络。

| 历史正文 | 全量路径 | 窗口路径 | 响应体减少 |
| --- | ---: | ---: | ---: |
| 5 MB | 44.79 ms | 14.79 ms | 80.39% |
| 20 MB | 254.93 ms | 21.24 ms | 95.11% |
| 40 MB | 537.69 ms | 24.24 ms | 97.56% |

固定每页 100 条仍可能携带数 MB 正文，因此窗口先查询 ID 和字节长度，再读取预算内正文。单条超过预算时仍完整返回，不截断内容。

## 本地回放入口

在 client 目录运行 `npm run dev -- --host 127.0.0.1`，访问 `/performance.html`。独立页面用内存数据覆盖自己的 fetch，不连接真实业务库。包含 100/500/2000 轮、加载全部、1000 次工具调用、5000 行代码、400 行表格、300 事件/秒、10 秒采集与主题/弹窗入口。

生产回放构建：PowerShell 中设置 `$env:CHATCODER_PERF_FIXTURE='1'`，运行 `npx vite build --outDir .cache/perf-dist`，再运行 `npx vite preview --outDir .cache/perf-dist --host 127.0.0.1`。普通生产构建不会包含 performance.html。日志与临时产物统一在 client/.cache，已忽略入库。

按需后端诊断接口：`GET /api/diagnostics/performance`，包含消息窗口查询、转换/序列化、响应大小、连接积压与发送耗时、写队列待写数量，不记录正文。

## 已知边界

- 最终落库正文仍解析一次完整 Markdown 结构，尚未引入持久 AST 协议；大代码高亮和 DOM 挂载已分离。
- 4ms 是任务间预算，同步的单个终端 fit 或第三方编辑器布局不能被抢占。
- 超预算单条消息完整返回；多个超长单条内容仍可能形成单次较大解析任务。
- PostgreSQL 的修订触发器已实现，未连接实机验证；当前性能数字仅代表本机临时 SQLite。
- 暂未对上下文拼装、token 统计和压缩链路完成 CPU 采样，因此没有凭推测迁移这些业务操作。
