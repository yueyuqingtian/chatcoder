## P0：优先阻断服务卡死

### 1. 倒序 cron 区间可能使服务事件循环卡死

- **证据**：`server/app/services/scheduled_service.py:121-130,152-156` 的倒序区间用 `while cur != end` 递增；`_norm` 只将周字段的 7 归一为 0，不会让分钟等字段回绕。`server/app/gateway/routers/scheduled.py:90-97` 在异步请求中直接解析。
- **触发与影响**：输入 `50-10 * * * *` 等倒序分钟范围时，循环不会到达终点，集合持续增长；实时校验请求可能阻塞同一事件循环并耗尽内存。越界的倒序范围也绕过后续边界检查。
- **建议**：先验证每个端点；明确哪些字段支持环绕，再用有界序列实现，并正确处理步长；其他倒序范围直接返回校验错误。避免在事件循环内执行可能无界的计算。
- **验收**：覆盖倒序、越界、周日 0/7、环绕及步长组合；请求在限定时间内返回，其他健康检查仍可响应；正常表达式结果不变。

## P1：安全、数据与任务可靠性

### 2. 本地 WebSocket 缺少来源和身份校验

- **证据**：`server/app/gateway/ws.py:204-213,224-246` 接受全局及会话连接；`server/app/orchestration/browser/bridge.py:56-68,86-90` 登记并优先选择最近的兼容浏览器宿主；会话通道处理审批和取消见 `ws.py:263-291,315-325`。
- **触发与影响**：恶意网页或可访问服务的进程可以尝试连接本地 WebSocket；浏览器跨源 CORS 规则本身不能保护 WebSocket。伪造宿主可能收到后续浏览器操作参数并伪造结果；知道有效标识时还可能回应审批或取消运行。`server/app/core/config.py:16` 默认监听 `0.0.0.0`，直接运行服务时暴露面可能更大；实际桌面启动配置应单独核对。
- **建议**：设计 HTTP 与 WebSocket 一致的本地身份认证，启动时生成随机凭据并安全传递给可信桌面客户端；对浏览器来源严格校验，并限制宿主注册。默认只监听回环地址，远程访问须显式配置。仅靠 Origin 不能阻挡非浏览器本地进程。
- **验收**：未知来源、缺失或错误凭据无法连接或注册宿主；合法桌面客户端、重连、审批和浏览器代理均正常；非回环监听需显式开启。应实际验证 Electron `file://` / 开发模式来源及凭据传递方式。

### 3. 安装包可能携带构建机的敏感配置

- **证据**：`package.json:64-66` 直接把 `server/.env` 复制到安装包；`.github/workflows/release.yml:124-129` 将 `SERVER_ENV` 写入该文件供打包；`server/app/core/config.py:26,30` 包含 API 密钥和 JWT 密钥配置项。
- **触发与影响**：若构建或发布环境的该文件包含真实密钥，获得安装包的人可以读取这些值。这里是有条件的泄露风险，本次没有查看或披露本机密钥内容，也未检查实际发布包。
- **建议**：区分可公开的运行配置和发布密钥，安装包仅包含无敏感信息的模板；敏感配置通过安全的用户侧配置或服务端注入。发布前扫描解包产物中的敏感字段，确认 CI Secret 是否本就被设计为公开。
- **验收**：使用带测试假密钥的构建环境打包并解包，确认假密钥未出现；安装及首次配置流程可用；排查历史发布包后按需轮换已暴露凭据。

### 4. 审批或提问答案在断线时可能被静默丢弃

- **证据**：`client/src/api/ws.ts:206-210` 在连接未打开时不发送且不返回失败；`client/src/store/chat.ts:2369-2392` 和 `client/src/store/sideChat.ts:321-331` 发送后立即移除本地待处理项。后端仅在收到回执时处理（`server/app/gateway/ws.py:263-291`）。
- **触发与影响**：断线期间点击允许、拒绝或提交回答，操作可能没有送达，但本地卡片已消失。主会话重连后有未决项对账（`client/src/store/chat.ts:4300-4341`），卡片可能重新出现，但之前的答案不会自动恢复；侧会话可能继续隐藏待处理项，任务仍在等待。
- **建议**：发送状态显式反馈；以服务端确认或未决项对账为准完成出队，保留用户输入并允许重试。确认协议应考虑重复提交的幂等性及超时。
- **验收**：分别对主/侧会话模拟断线、发送后断线及重连；允许、拒绝和结构化回答均不静默丢失，不重复处理，待处理状态与服务端一致。

### 5. 定时任务结束时会覆盖较新的排期

- **证据**：`server/app/services/scheduled_service.py:337-380` 领取时原子推进下一次运行时间；`server/app/services/scheduler_loop.py:107-115,128-129` 完成时传入领取快照；`scheduled_service.py:311-325` 无条件覆盖当前 `next_run_at`。编辑 cron 也会重算该字段（`scheduled_service.py:266-275`）。
- **触发与影响**：长任务运行时修改 cron，或多个周期的运行交错完成，旧运行完成后可能把过期快照写回，造成重复触发、排期错误或错过任务。
- **建议**：将领取推进和运行结果记录解耦；完成回执不回写已由领取或编辑维护的排期，必要时为单次运行记录独立标识和版本。
- **验收**：模拟长任务期间修改 cron、重叠运行反序结束以及手动试跑；下一次执行时间保持最新配置，任务不会重复领取。

### 6. 定时任务可能将失败或中断显示为成功

- **证据**：`server/app/services/scheduler_loop.py:105-110` 忽略 `engine.start_turn` 的返回结果，只要没有抛异常就记录 `ok`；`server/app/orchestration/engine.py:1312-1316,1329,1341,1925-1928` 等路径以返回结果表示失败或中断。
- **触发与影响**：执行器以正常返回值报告失败或中断时，定时任务最后状态可能显示成功，用户难以发现任务未完成。
- **建议**：以持久化的 turn 最终状态为准映射成功、失败、中断及其他非终态，记录适当的错误原因；明确等待用户处理时的展示。
- **验收**：覆盖成功、会话或项目不存在、执行失败、取消及等待审批等分支，定时任务状态与 turn 一致。

## P2：体验与构建可靠性

### 7. 侧会话旧快照可能覆盖较新的实时消息

- **证据**：`client/src/store/sideChat.ts:111-125` 直接将 REST 结果替换状态，`132-149` 实时追加消息，`175-195,224-245` 可在实时事件期间发起多个刷新。
- **触发与影响**：较早发出的请求晚于新消息事件或较新的请求返回时，旧快照可能覆盖已显示的消息或运行状态，直至后续刷新。
- **建议**：为每个会话与数据类型增加请求代次，并结合服务端版本或事件序号合并快照和增量；仅靠请求代次不能处理请求期间到达的实时事件。
- **验收**：控制 REST 返回顺序，让新消息和结束事件先到；最终状态包含最新消息、运行状态准确，切换会话不串数据。

### 8. 定时任务预览会跳过符合条件的分钟

- **证据**：`server/app/gateway/routers/scheduled.py:79-86` 得到下次时间后又加一分钟；`compute_next_run` 本身查找严格晚于传入时间的下一分钟。
- **触发与影响**：对 `* * * * *`，预览显示 12:01、12:03、12:05，误导用户以为每两分钟执行一次；本次只验证了预览算法，不声称实际调度同样跳过。
- **建议**：以刚得到的时间作为下次搜索游标，并核对时区、夏令时与稀疏表达式语义。
- **验收**：每分钟表达式连续展示相邻分钟；每日、每周及跨时区边界的预览与实际调度口径一致。

### 9. 引用主对话后，侧会话用户消息可能突然变长

- **证据**：`client/src/store/sideChat.ts:269-285` 把引用上下文拼入发送内容，但乐观消息展示输入的问题；`server/app/gateway/routers/turns.py:71-88,145-150` 持久化并广播完整内容；`client/src/components/chat/UserBubble.tsx:17-19` 直接展示持久化文本。
- **触发与影响**：发送引用后，乐观气泡被服务端消息替换，长引用可能突然占满气泡并遮住用户真正的问题。
- **建议**：区分展示内容和提交模型的引用上下文，提供明确的引用摘要或可展开区域，并兼容已有历史消息与导出。
- **验收**：发送、重开会话和导出时均能辨认原问题及引用，长引用不会隐藏问题，旧记录仍可阅读。

### 10. 通用构建入口未重建索引 worker

- **证据**：`package.json:11-12` 的 `build:all` 仅运行主后端构建；`package.json:60-62` 又要求打包 `server/dist/chatcoder-index-worker`。`build-release.ps1:45-47` 的发布脚本则分别构建主程序及 worker。
- **触发与影响**：通过 `npm run build:all` 从干净目录构建时，worker 目录可能缺失而导致打包失败；目录残留时可能带入旧 worker。本次未执行完整打包验证。
- **建议**：统一构建入口，清理并重建两个后端产物，打包前校验其来源和版本；避免不同入口产生不同结果。
- **验收**：在干净构建目录运行各受支持入口，检查 worker 存在且与当前代码一致；故意留下旧产物时也不会被误打包。

### 11. 空 cron 可被保存并阻塞同批定时任务

- **证据**：`server/app/gateway/schemas.py:263-265` 允许可选字符串；`server/app/services/scheduled_service.py:270-275,286-288` 仅对真值 cron 校验，却会写入非 `None` 的空字符串。领取时 `scheduled_service.py:362-380` 在同一批次逐条计算下次时间；异常由 `scheduler_loop.py:166-174` 统一捕获。
- **触发与影响**：通过更新接口提交空字符串后，非法值可持久化；该任务到期时计算失败，当前领取批次不能正常完成，其他任务也可能受阻。本次为代码路径分析，尚未执行完整调度复现。
- **建议**：区分未提供字段与空值，对所有提供的 cron 做非空及格式校验；逐条隔离历史非法记录并显示错误，避免单条坏数据影响其他任务。
- **验收**：空字符串、空白字符串均被拒绝；人为插入一条历史非法数据后，其他到期任务仍能领取，问题任务状态可见且不会无限刷错。

### 12. 桌面端语言偏好可能未同步到后端

- **证据**：`client/src/store/ui.ts:412-424` 使用相对地址发送设置并吞掉失败；桌面应用通过 `electron/main.cjs:1305` 的 `loadFile` 加载，而项目 API 端口解析见 `client/src/api/client.ts:79-93`。
- **触发与影响**：打包版的相对请求可能无法访问本机后端；自定义开发端口也可能绕开正确配置。界面本地偏好仍会改变，但后端语言设置可能保持旧值；尚需在对应运行环境实测。
- **建议**：复用统一 API 客户端，按设置项保存规范处理失败并提示重试；确认本地偏好与后端的权威来源。
- **验收**：在打包版和自定义开发端口下切换语言，重启后界面与后端设置一致；模拟失败可见且不误报保存成功。
